InterMine314 performance review

Baseline 6a85ed7 and implemented uplift · Python 3.14.5 / CI current 3.14 · Intel Core Ultra 7 265K · 18 CPUs exposed to WSL · 20-core host recommendations

Implemented performance uplift

All 25 included opportunities have implementation, replacement and regression-test evidence below; P09 remains excluded by the user. The code inventory covers 77 runtime modules and 14,132 lines. Ten phases and 32 tasks are tracked with commit and CI evidence. Version remains 0.1.8; this work does not publish a release. Accepted status comes from the phase ledger, and the final evidence commit may follow the CI-verified implementation head.

Hardware and resource policy

Intel Core Ultra 7 265K has 20 cores (8 P + 12 E); this WSL guest exposes 18 CPU/affinity slots. Default advisory native CPU budget is 16, with cpu8/cpu6/cpu4/cpu2 options and affinity/quota clipping. Native stages share admission instead of summing independent pools. Existing external pools are reported and may exceed the advisory budget. There is no verified P/E affinity map, bare-host 20-core sweep, or free-threaded/native-wheel certification. Python 3.14.5 local tests use the GIL; current Python 3.14 is verified separately in CI.

Current processing path

Immutable execution snapshot → shared host fetch permits → terminal-status-validated pages → typed Arrow conversion → bounded native write → validated Parquet parts and relative manifest → atomic publication → DuckDB SQL → owned Arrow reader or deliberate DataFrame materialization. Pending, buffered and emitting pages remain accounted until consumption. CSV compatibility APIs remain available, while durable analytics, manifests and evidence use Parquet. DuckDB holds the SQL catalog. XML/HTTP scratch, native spill and known-length upload staging are temporary, not alternative analytical stores.

Final measurements and tradeoffs

259 new trials cover 37 configurations, seven repetitions each, with full result-value equality on every run. Configurations run in fresh processes with one warmup and randomized case order. HTTP compares identical 32,000-row gzip fixtures against baseline 6a85ed7; final writer uses one million rows, SQL/Polars four million integer rows, and spawned transforms sixteen coarse path tasks. The smallest worker count within 5% of the best median is selected subject to summed process RSS <=4 GiB. These choices describe these fixtures, not revised universal defaults. At four HTTP workers the 5 ms pipeline median changes from 0.2201s to 0.2318s (5.3% slower); at 30 ms it changes from 0.4168s to 0.4137s. The small fast-fixture regression is retained alongside stronger terminal-status, schema, memory and publication checks; those checks add work, but this experiment does not isolate their causal contribution. At the recommended low-latency count of two, the current median is 0.2295s. New measurements never overwrite the 689 historical trials (482 selected).

Memory and uncertainty

Final RSS is sampled every 10ms across the process tree; summing resident sets counts shared pages once per process and is not unique PSS. CPU includes exited children. Peak includes retained setup/warmup/validation allocations; validation itself is outside timed actions. Seven repetitions support descriptive min/median/max/CV, not production p95 or a confidence interval. Spawn 16 reached 2588 MiB versus 775 MiB at four, while median time fell from 0.767s to 0.512s. Byte accounting remains an estimate, a first oversized page can exceed it, and DuckDB memory_limit is not a hard RSS limit. Relationship fanout and external pools require workload-specific monitoring.

Implemented conversion and metadata evidence

Seven paired production conversion trials preserve full-frame parity: inferred conversion median 0.09820s → 0.02710s (3.62x), model conversion 0.03724s → 0.02432s (1.53x). Seven paired 1000-class model trials preserve descriptor fingerprints: 0.03580s → 0.01137s (3.15x). Separate Python allocation peaks fall from 18,723,917 to 3,119,573 bytes; this is tracemalloc, not RSS/native memory. Phase 4 container accounting estimates 6,555,176 bytes versus a 4,643,400-byte unique Python graph on its flat fixture. These isolated improvements must not be multiplied into an end-to-end claim.

Compatibility and ownership coverage

Legacy imports under intermine314.webservice, Query/Template results and list/helper contracts remain covered by the compatibility corpus and installed-wheel binding checks. Users replace imports of intermine with intermine314; an intermine namespace is not installed. Existing DataFrame returns, lazy object fields, explicit DOM responses, raw chart cardinality and custom execution hooks retain distinct semantics. New reader/path/prefetch/spawn APIs are opt-in. Tests cover late server-failure rollback, compressed sized XML, ordered-buffer bounds, exact numeric/nested schema cases, reader cancellation, borrowed resource lifetimes and mutation ownership. No authenticated production writes were exercised.

Immediate replacements and retained contracts

Every included opportunity has a completed implementation and an explicit removal/retention decision below; there is no deferred retirement cycle. Normal discovery no longer builds a full DOM, export no longer reassembles individual page rows, CSV paths no longer snapshot entire streams, identifier uploads no longer accumulate all IDs, and publication shares one owner-aware transaction. Precision guards and semantically distinct legacy return/input contracts remain. Git history is the recovery mechanism for replaced code.

Limits of certification

Public-mine optima, WAN retries/tails, remote snapshot stability, server offset-query plans, physical disk saturation, energy use, Windows execution and bare 20-core affinity remain unmeasured. Remote pagination still needs stable server ordering/data. Manifest fields are relative paths, size/mtime, row counts/groups, serialized schema and producer order; server releases, query hashes and content checksums are not promised. External files are validated; caches do not establish snapshot isolation. GUI plotting belongs on the main thread. Transform callback side effects outside assigned outputs are not transactional. Cross-process publication needs application coordination.
